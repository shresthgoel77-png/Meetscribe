### Transport and official contract

Read current official [STT REST](https://docs.gnani.ai/api/STT/speech-to-text), [TTS REST](https://docs.gnani.ai/api/TTS/tts-inference) and [voice catalog](https://docs.gnani.ai/api/TTS/available-voices) on this date. Authentication remains `X-API-Key-ID`. TTS's written response contract and format table specify binary `audio/wav`; this implementation does not follow the autogenerated sample that calls `res.json()` on audio.

- Added `electron/providers/speech/gnani.js`, separate from existing STT/LLM registries. No Electron/config/filesystem/logger imports or automatic network activity. Main callers explicitly supply credentials and audio/text; no UI or IPC was added.
- `transcribe({ apiKey, audio, signal }, { fetchImpl, timeoutMs })`: actual `Uint8Array`/Buffer PCM WAV bytes → multipart `audio_file` named `recall.wav`, `model=prisma-v3.0`, `language_code=hi-IN,en-IN`, `format=transcribe`, POST `https://api.vachana.ai/stt/v3`. FormData owns its multipart boundary. Returns only `{ text }`; typed `NO_SPEECH` and `INCOMPLETE_TRANSCRIPT` errors prevent empty/truncated text entering a later answer pipeline.
- Deliberate application input scope: mono 16-bit PCM WAV at 8000–48000 Hz. Gnani also accepts compressed formats, but this adapter requires PCM WAV so it can enforce the 25-second Recall cap from actual sample bytes without a decoder dependency or trusting a caller's duration claim. It checks RIFF/chunk lengths, padding, PCM format, alignment and byte rate. No meeting-audio conversion code was changed.
- `synthesize({ apiKey, text, model, voice, language, speed, signal }, deps)`: POST JSON to `https://api.vachana.ai/api/v1/tts/inference`, default `timbre-v3.0`/`Shivani`, language `auto`, numeric speed 1 (allowed 0.85–1.15). Also supports the separate v2.5 catalog/default Nalini; cross-model voices are rejected locally. Explicit audio config: `linear_pcm`, `wav`, mono, `sample_width: 2`, `sample_rate: 24000`. Returns `{ audio: Buffer, mimeType, sampleRate, durationSeconds }` after binary WAV/header validation; never JSON/base64 success.
- Application caps (not additional Gnani limits): upload 3 MiB, STT JSON 64 KiB, TTS audio 4 MiB, error body 16 KiB, TTS text 2000 UTF-16 code units. The provider's published REST clip limit is 30 seconds. No numeric provider text ceiling is assumed.
- Deadline 30 seconds by default, configurable up to 60 seconds; covers fetch/upload/body reading. Caller cancellation and timeout abort the underlying request and cancel a stalled body. A race also bounds injected fetches that ignore abort; late results are discarded. Fixed URLs, redirect rejection, MIME/status checks and streamed byte counting apply. No automatic billable retries, payload/key logging, raw provider errors or retained causes/abort reasons. Stable sanitized codes cover nested STT errors, flat TTS errors, auth detail envelopes and validation arrays.
- Added `tests/recall-speech.test.js` and optional `scripts/recall-speech-smoke.js`. The latter requires `--live --user-recorded --clip <local-PCM-WAV-path>` plus securely supplied `GNANI_API_KEY`; it is not in package scripts. It uploads the explicit clip and a fixed non-meeting TTS phrase, prints only result/format metadata, writes no audio/transcript/credential files and supports Ctrl+C cancellation.

### Evidence and validated answer contract

```text
Evidence = { evidenceId, sessionId, title, startedAt, section, text, locator, contentHash }
Claim = { text, evidenceIds: [evidenceId], citations: [{ evidenceId, quote }] }
Answer = { requestId, status: 'answered' | 'insufficient_evidence', text, claims: Claim[], sources: Evidence[], coverage, uncertainty }
```

- Evidence IDs are deterministic `E` plus 24 lowercase SHA-256 hex digits derived from session ID, source content hash and locator; at most twelve IDs are eligible for any one request. This Stage 4 refinement replaces the earlier rank-position IDs so unrelated insertions do not rename a passage. Every use still requires the current request's freshly retrieved whitelist. Session IDs are non-empty stored IDs at most 128 code units, used only for validated DB lookups. Titles are at most 240, section labels 120 and text 1600 UTF-16 code units. `startedAt` is an ISO string or null. These fields are untrusted data, not instructions, URLs to visit, markup to execute or filesystem paths. Title-only matches cannot ground a factual claim. Retrieval must consider every eligible complete meeting before selecting bounded evidence, including imports/pastes; exclusions and retry tracking remain as established in Stage 1.
- A locator is one of `{ kind: 'transcript', segmentIndex, from, to, startSeconds, endSeconds }`, `{ kind: 'notes', path, from, to, projection?, taskRange? }`, or `{ kind: 'markdown', from, to }`. Offsets are integer, half-open UTF-16 offsets after CRLF/CR normalization to LF. Simple fields/Markdown/transcripts use the exact source-string slice. Structured note objects use deterministic `section`, `action`, `record` or `participant` projections defined in `recall-retrieval.js`, retaining labelled source values together; offsets refer to that projection string. A long action's optional `taskRange: { from, to }` slices its actual task string before repeating the full owner/due context. Segment indices refer to the saved array. `path` is at most six string/integer parts interpreted only through a fixed allowlist of known note fields/array indices, never eval/SQL/JSONPath or arbitrary object/prototype traversal. Times are finite non-negative seconds or null; paste/synthetic/unknown timing is null, never presented as real recording time. Markdown locates `_rawMarkdown`. These projection extensions let source opening reconstruct composite facts without pretending they came from one raw field.
- `contentHash` is `sha256:` plus 64 lowercase hex digits, computed in main over a canonical JSON snapshot of `{ sessionId, title, startedAt, notes, transcript }` from the saved row (recursively sorted object keys, original array order). The full snapshot is not sent to the assistant/LLM. Any source edit changes the hash. Recheck existence, eligibility and hash before publishing an answer and on source opening; missing/changed sources return `SOURCE_CHANGED`. Source opening resolves the retained answer's evidence ID in main, not a renderer-supplied path or arbitrary session query.
- An answered result has 1–3 claims, each at most 240 code units with 1–3 citations. Each citation names an ID supplied to this request and an exact, non-empty quote of at most 240 code units occurring in that evidence text. Main constructs `text` from the validated claims in order; sources contain exactly the cited evidence union. Unknown/duplicate evidence IDs, invalid quotes, oversized output or extra unrecognized output fields fail validation. Source excerpts remain visibly verifiable. Shape/quote checks do not prove semantic entailment: the answering instructions must restrict claims to evidence, preserve contradictory decisions with both sources, and match the question's language.
- `insufficient_evidence` has empty claims/sources and a short localized admission of insufficient evidence; no model-invented facts or mandatory LLM call. Answers normally use 1–3 short sentences and about 60 words or fewer. If TTS later fails, retain the already validated text/sources and report the speaking-stage error; never turn valid text into a speech-success claim.
