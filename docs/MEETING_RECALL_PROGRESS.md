### Saved data and eligibility

`electron/db/sessions.js` owns an in-memory sql.js database persisted to `userData/novameet.db`. Its fixed CRUD statements are parameterized; only allowlisted columns are updateable. `listSessions()` has **no default limit** and returns all rows ordered by `started_at DESC`. Do not replace/migrate the DB or expose SQL to Recall UI.

| Data | Actual persisted / returned shape |
| --- | --- |
| Session | `id`, `title`, `meeting_url`, `started_at`, `ended_at`, `duration_seconds`, `audio_path`, `transcript`, `notes`, `notion_page_url`, `status`, `last_error`. Dates are stored strings; optional columns can be null. |
| Transcript | JSON text in SQLite; deserialized with fallback `[]`. Normal STT segments: `{ speaker, text, startTime, endTime }`, times in seconds. Successful JSON parsing does not validate segment shape. |
| Pasted transcript | Paragraph array `{ speaker, text, start_time, offset_seconds }`; offsets are synthetic `index * 5`, not recorded speech timestamps. No audio path is required. `transcriptToText`/`TranscriptViewer` read `startTime`, so these aliases are not currently normalized there. |
| Structured notes | JSON object; normalized `title`/`meeting_title`, participants `{ label, name, role, identity_confidence }` plus attendees, `sections`/`topics`/`key_points` aliases containing heading/content/summary/options/decision/open fields; flat action items with task/owner and optional priority/due. Other prompt fields include summary, decisions, questions_unresolved, notable_mentions, status_update and next_meeting. |
| Markdown / fallback notes | Markdown: `{ _rawMarkdown, title, meeting_title }`; invalid structured output retains `_rawResponse` and fallback summary fields. Main stamps `_llmProvider`, `_llmModel`, legacy `_geminiModel`, `_sttService`, optional `_sttModel`; edits preserve metadata and add `_editedAt`. |

Lifecycle: recording → transcribing → generating → complete; optional Notion upload uses uploading → complete, failures use error. Crash recovery can produce recorded; stale recording rows become error. Audio imports enter transcribing; pasted transcripts enter generating and use a separate asynchronous notes/upload path. Imported sessions can lack `ended_at` and duration: `createSession` does not insert the duration passed by the audio-import caller. Do not require audio, duration, end time or meeting URL for otherwise eligible complete records.

Recall must retrieve across **all complete, still-existing saved records**, including imports and pastes, and skip non-complete states and the actual active recording. Main's `isRecording`, `currentSessionId`, `captureMode` own recording state; `currentSessionId` is not cleared after stop, so excluding that ID unconditionally would wrongly exclude the last finished meeting. Renderer `recordingSessionId` and its single processing indicator are not authoritative eligibility controls.

No comprehensive main-process in-flight processing set exists: `cancelledSessions` tracks deletion, not every processing job. Retries enter `runProcessingPipeline` after a `setImmediate`, leaving the previous status briefly visible; the standalone Notion retry does not set uploading while awaiting the API. Future small hooks must mark processing synchronously and clear in `finally`, covering regular runs, retries and pasted transcripts. A status-only check misses these windows. Deletion physically removes the row and audio/waveform; retrieval/source opening must recheck existence and eligibility and avoid stale cached evidence. Pasted processing lacks the regular pipeline's cancellation guard; this is an inspected limitation, not a reproduced failure or an audit fix.

### Retrieval, answers, settings and source navigation

- `renderer/lib/meetingSearch.js` is existing renderer-only lexical search: Unicode tokenization, English stemming/concept synonyms, BM25 field weights, prefix/typo matching, phrases, per-object/array WeakMap caches, and one session result with snippet/terms. It searches title, structured/Markdown notes and transcript text from the supplied array; it does not enforce Recall eligibility, emit stable evidence locators, translate Hinglish, or answer. Preserve its behavior; build separate bounded passage retrieval in main, keeping segment/field/character locations and deterministic evidence IDs.
- `services/notes.js` is note generation, not a general answering controller. It uses `resolveTargets` (saved `llmProvider`/`llmModels`, optional `llmFallback`) and `notes-normalize.js` to serialize transcripts and parse notes. Recall should call the existing low-level LLM `generate({ systemPrompt, userPrompt, model, config, json })` contract from its own controller, with separate instructions and request state; do not invoke note generation or stamp meeting provenance for answers.
- `providers/index.js` registers meeting STT Google/Sarvam/AssemblyAI/Groq and LLM Gemini/Groq/Claude. `registry.js` validates metadata/functions, strips runtime functions from descriptors, resolves models and checks required credentials. Gemini uses its SDK; Groq and Claude use main-process `shared/http.js` fetch wrappers with status/retry-after errors. These provider generate methods do not currently accept a shared cancellation signal. `shared/wav.js` reads WAV headers/peak/duration, chunks assumed 16 kHz mono PCM and merges transcript segments; it is not a live microphone/STT/TTS service. Keep Gnani separate from the meeting provider registries and defaults.
- `utils/config.js` stores schema defaults in `novameet-config`, applies existing legacy-model migration when read, resolves provider models and synchronizes historical key aliases. Defaults remain Google meeting STT, Gemini LLM, JSON notes and disabled LLM fallback. No live config was loaded during audit.
- Settings flow: `Settings.jsx` loads descriptors plus full config, builds a local form/initial snapshot, guards dirty navigation, then `onSave(form)` → `app.jsx:updateMultipleConfig` → preload `config:set-multiple` → main `setMultipleConfig` → store; app rereads config. Main also applies auto-launch/detection/theme/capture side effects. `SettingsParts.jsx` supplies reusable controls; `providers/ProviderSection.jsx`, `ModelSelect.jsx`, `providerIcons.js` control meeting credentials, selection, tests and fallback. Recall settings must have their own save payload/store namespace and redacted read surface; never round-trip meeting settings through Recall.
- Source-opening path today: overlay `openSession(id)` → main focus + `app:open-session { sessionId }` → `app.jsx:openSessionById` fetches current row → guarded `openSession` → `NoteViewer`. Default tab is summary. No passage target/highlight or cross-component seek argument exists. `TranscriptViewer` renders speaker/time/text and local filters; `note/AudioPlayer.jsx` seeks only internally and plays `meetscribe-audio://session/<id>` via main's range-capable protocol. `session:open-recording` reveals a file in Explorer, not a cited passage. Add only a validated source locator through this route later; synthetic paste offsets must not be presented as real audio times.
- `renderer/lib/format.js` supplies display titles, local date/time, duration and clock formatting plus speaker labels. Its date display locale is en-US; this does not implement answer-language matching.

### Audio ownership and disclosure

`renderer/app.jsx` owns meeting MediaRecorder/streams/AudioContext: system `getDisplayMedia` audio plus optional microphone `getUserMedia` mixed to a destination, WebM chunks each second. Main approves screen-loopback capture, appends chunks to `userData/recordings/<id>.webm`, waits for the stop sentinel, and converts to 16 kHz mono PCM WAV via FFmpeg. Conversion applies volume gain 4. Windows fallback `electron/audio/recorder.js` owns a separate FFmpeg process, probes devices, prefers WASAPI, falls back to DirectShow/microphone, may save detected device choices, and stops with `q` then a kill timeout. Do not reuse these meeting singletons/channels for Recall audio.

Existing main renderer also briefly requests/stops the Windows mic at app startup for permission; preserve that behavior without copying it into Recall. `services/permissions.js` implements macOS TCC checks/requests/settings and reports not-applicable on Windows; it is not proof of Windows microphone availability. `audio/ffmpeg-path.js` resolves dev Windows `assets/ffmpeg/*.exe`, packaged `resources/ffmpeg/*.exe`, then PATH; macOS has architecture folders/userData/Homebrew candidates. Packaged paths were inspected, not executed.

Recall must default to Text and acquire its own microphone only after explicit Voice Start, with Stop/cleanup on mode/window/lifecycle changes. Gnani Prisma STT → same evidence answer pipeline → Gnani Timbre TTS is required; no browser speech substitute. Keep secrets and cloud traffic in main. Disclose that query/evidence goes to the answering LLM and voice audio/text goes to Gnani. **System loopback may record spoken assistant answers even through headphones.** Provide mute/stop; never pause the meeting to suppress capture.
